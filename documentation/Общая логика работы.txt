1.1. Как работает аутентификация пользователя через имитатор ЕСИА. 

Пользователь нажимает кнопку аутентификации через ЕСИА
на данном этапе не реализовано взаимодействие с реальными госуслугами, вместо этого имитатор

Вот как аутентификации через имитатор должна работать:
в БД есть таблица esia_account, её поля: 
-- Создаем таблицу для имитации базы данных Госуслуг
CREATE TABLE esia_accounts (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    login VARCHAR UNIQUE NOT NULL, 
    password_hash VARCHAR NOT NULL,
    first_name VARCHAR NOT NULL,
    last_name VARCHAR NOT NULL,
    birth_date DATE NOT NULL , 
    gender gender_enum NOT NULL -- Используем  ENUM, который был создан ранее

);


при нажатии на кнопку "зайти через Госуслуги" мы переходим на страницу 
захода в  наш имитатор "госуслуг"(ЭТО НЕ ОТДЕЛЬНЫЙ САЙТ - это просто страница нашего приложения)
и на ней 2 поля - логин и пароль от аккаунта в "имитаторе" госуслуг.
На бэкенде мы:
1-по этим 2м полями находим пользователя и получаем из esia_account таблицы его esia_id,фамилию ,имя ,пол ,дату рождения.
Если найти не удалось - возвращаем ошибку на фронтенд.

2-Проверяем - есть ли пользователь (user),который уже привязан к этому аккаунту имитатора госуслуг(у user есть поле   esia_id UUID UNIQUE NOT NULL) 
Если такой пользователь есть - то просто запускаем его в систему(даем ему JWT)
Если нет пользователя,который привязан к этой записи,то регистрируем его
 ->создаем на их основе запись в таблице users.
(И потом только отдаем JWT) 

Регистрации в имитатор госуслуги не будет.
Пользователь в наш имитатор мы добавим через БД сами - мы сами в бд загрузим УНИКАЛЬНЫЕ комбинации логин-хэш пароля.



1.2)Регистрация и вход для партнеров:
На данном этапе не будет возможности регистрироваться как партнер.
Данные для аккаунтов партнер будут записаны в бд напрямую(через sql запрос в pgAdmin)

Будет только страница захода в профиль(по логину и паролю).

У партнеров будут свои страницы(и соответсвенно API-ручки), доступные только им


2)Общий вид для  пользователей
2.1. снизу 4 иконки с подписями (слева направо Лента Метчи Чаты Профиль)
2.2. нажимаю на иконку Профиль: вижу свою main фото(под ним располагаются все остальные фотографии и кнопка редактировать, чтобы удалить или добавить фото) и данные анкеты (имя фамилия, дата рождения, пол, о себе, город) и кнопка редактировать снизу справа под областью о себе, чтобы изменить данные в поле "о себе" и кнопка сохранить симметрично слева (пока данные не изменены, она неактивна)
2.3. нажимаю на иконку чаты: вижу список своих чатов в формате :main фото пользователя(над ним его имя) в круглой форме и отображение последнего сообщения в чате
2.3.1. чат выглядит как в самых распростарнённых мессенджерах, текст отправителя справа с фоном для сообщения одного цвета, сообщение  от получателя с фоном другого цвета слева, сообщения идут друг под другом
2.3.2. Сверху над чатом поле, где видно небольшую main фото профиля в круге и имя
2.3.3. снизу поле в которое нужно писать сообщение. прии нажатии на него выдвигается клавиатура (как в Андроид системе), справа этого поля иконка эмодзи, нажав на которую появляется стандартный набор эмодзи для Андроид и ещё правее иконка, нажав которую сообщение отправится в чат
2.3.4. при нажатии на имя человека в чате, происходит переход на вкладку метч, где отображается только этот пользователь (чтобы посмотреть данные его)
2.4. нажимаю на метчи: вижу список пользователей в формате : main фото с возможностью листать фото и данные пользователя (имя фамилия, дата рождения, пол, о себе, город), та же лента, но с фильтром на метч и без возможности оценивать
2.5. нажимаю на ленту: вижу каждого пользователя отдельно в формате main фото с возможностью листать фото и данные пользователя (имя фамилия, дата рождения, пол, о себе, город), но уже с логикой свайпов(влево - дизлайк, вправо - лайк), пока не совершён свайп, другого пользователя не появится, когда сделан свайп в таком же формате появляется анкета другого пользователя
3)Общий вид для партнеров
3.1. У партнёров одна "страница" профиль, где я вижу main фото заведения (под ним располагаются все остальные фотографии и кнопка редактировать, чтобы удалить или добавить фото) и необходимые данные заведения(согласно логической схеме) и кнопка редактировать снизу справа под областью, чтобы изменить данные и кнопка сохранить симметрично слева (пока данные не изменены, она неактивна)
3.2. Так же под данными заведения есть форма добавить акцию, в которой заполняются поля Название акции и информация о ней и срок действия и аналогично кнопки редактировать сохранить
3.3. справа в верхнем углу будет кнопка выйти из аккаунта и откроется снова поле регистрации в аккаунт
