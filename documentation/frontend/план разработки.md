# 🚀 План разработки Android-приложения (по фазам)

Твой Android-клиент должен развиваться параллельно с бэкендом. Не жди, пока бэкенд будет готов полностью. Как только на бэкенде появляется эндпоинт — сразу пиши под него экран.

#### 🟢 Фаза 1: Фундамент (1-2 дня)
1.  Создай проект в Android Studio (Empty Activity, Jetpack Compose).
2.  Добавь зависимости в `build.gradle.kts`:
    *   **Retrofit + Gson** (для сетевых запросов).
    *   **OkHttp Logging Interceptor** (чтобы видеть в Logcat, что летит на сервер).
    *   **Navigation Compose** (для переходов между экранами).
    *   **Coil** (для загрузки картинок по URL).
    *   **ViewModel Compose** и **Coroutines**.
3.  Настрой `BASE_URL` в константах (`http://10.0.2.2:8000/api` — **ВАЖНО:** `10.0.2.2` — это IP твоего компьютера с точки зрения эмулятора Android, `localhost` не сработает!).
4.  Настрой **`network_security_config.xml`** (разреши cleartext traffic для `10.0.2.2`), иначе Android заблокирует HTTP-запросы.

#### 🟡 Фаза 2: Аутентификация (3-4 дня)
1.  **Создай `TokenManager.kt`:** используй `EncryptedSharedPreferences` для сохранения JWT-токена.
2.  **Настрой Retrofit:** добавь `OkHttp Interceptor`, который автоматически подставляет `Authorization: Bearer <token>` в каждый запрос, если токен есть.
3.  **Экраны `WelcomeScreen` и `EsiaLoginScreen`:** Сверстай по промпту из Figma.
4.  **`AuthViewModel`:** 
    *   Логика вызова `POST /auth/esia-login`.
    *   Обработка успеха (сохраняем токен, переходим на главный экран).
    *   Обработка ошибки (показываем Toast или текст под полем ввода).
5.  **Проверка:** Запускаешь эмулятор, вводишь логин/пароль от имитатора ЕСИА (из твоей БД), попадаешь на пустой экран "Главная".

#### 🟠 Фаза 3: Нижняя навигация и Профиль (2-3 дня)
1.  Создай `Scaffold` с `NavigationBar` (4 иконки: Лента, Метчи, Чаты, Профиль).
2.  **`ProfileScreen`:**
    *   Запрос `GET /users/me`.
    *   Отображение данных: имя, город, био, фото.
    *   Используй **Coil** для загрузки фото по URL (`AsyncImage`).
    *   Реализуй кнопку «Редактировать» (диалог или переход на экран редактирования) и отправку `PATCH /users/me`.
3.  **Загрузка фото:** Используй `ActivityResultContracts.GetContent()` для выбора фото из галереи. Отправляй `multipart/form-data` на `POST /photos`.

#### 🔵 Фаза 4: Лента и Свайпы (4-5 дней) — *Самое интересное в UI*
1.  **`FeedScreen`:**
    *   Запрос `GET /feed`.
    *   Отображение карточки пользователя (фото, имя, возраст, био).
2.  **Механика свайпов:** 
    *   В Compose для этого можно использовать `Draggable` или библиотеку **Swipeable** (встроена). 
    *   *Совет:* Если реализовывать свайпы вручную сложно, сделай для MVP две кнопки внизу: «❌ Дизлайк» и «❤️ Лайк». Это спасет тебе неделю времени, а выглядеть будет стильно. 
3.  **`FeedViewModel`:** Вызов `POST /contacts/swipe`. 
4.  **Анимация мэтча:** Если бэкенд вернул `is_match: true`, покажи модальное окно «У вас мэтч!» с кнопкой «Перейти в чат».

#### 🟣 Фаза 5: Список чатов и Мессенджер (4-5 дней)
1.  **`ChatListScreen`:** Запрос `GET /chats`. Отображение списка (фото собеседника, имя, последнее сообщение, время).
2.  **`ChatScreen`:**
    *   Запрос `GET /chats/{id1}/{id2}/messages`.
    *   **UI:** Используй `LazyColumn` с `reverseLayout = true` (чтобы новые сообщения были снизу).
    *   Отображение сообщений: свои (справа, цветной фон), чужие (слева, серый фон).
    *   **Поле ввода:** `TextField` + иконки (эмодзи, отправить).
    *   **Отправка:** `POST /chats/.../messages`.
3.  **Прочитанные:** При открытии чата отправляй `PATCH /chats/.../read`.

#### 🟢 Фаза 6: Инвайты и Промокоды (3-4 дня)
1.  В экране `ChatScreen` добавь кнопку (иконку) «Предложить свидание».
2.  При нажатии: открывается список офферов (`GET /offers`).
3.  Пользователь выбирает оффер -> отправляется `POST /invites`. В чате появляется сообщение со ссылкой.
4.  **Обработка ссылки:** Если пользователь получает сообщение со ссылкой, при клике на неё открывается экран проверки `GET /invites/{token}` и кнопка «Принять» -> `POST /invites/{token}/accept`.

#### ⚫ Фаза 7: Партнерский кабинет (3-4 дня)
*   Это отдельный флоу. 
*   Экран логина партнера (отправляет `POST /auth/partner-login`).
*   Экран профиля партнера с загрузкой фото и CRUD-операциями для офферов (`POST/PATCH/DELETE /partners/me/offers`).

#### 🏁 Фаза 8: Тестирование и Полировка (2-3 дня)
1.  Проверь отображение клавиатуры (Android должен сам её выдвигать, но проверь `imePadding()` в Compose).
2.  Добавь состояния загрузки (кружочки `CircularProgressIndicator`), чтобы пользователь не смотрел на пустой экран.
3.  Проверь обработку ошибок сети (например, отключи Wi-Fi и посмотри, что покажет приложение).

---

### 💡 Три важных совета для Android-разработчика:

1.  **Не пиши всю логику в UI.** Если ты начнешь делать сетевые запросы прямо из `Composable`-функции, твой код превратится в кашу. Всегда: `Compose -> ViewModel -> Repository -> API`.
2.  **Используй состояния (State).** В Compose UI перерисовывается при изменении состояния. Сделай `data class UiState` внутри ViewModel (например, `isLoading`, `error`, `userData`), и пусть экран подписывается на него.
3.  **Картинки — это URL.** Бэкенд присылает тебе относительный путь (`/media/...`). В Android тебе нужно склеить его с базовым URL: `${BASE_URL}${photo.url}`. Иначе Coil не найдет картинку.
