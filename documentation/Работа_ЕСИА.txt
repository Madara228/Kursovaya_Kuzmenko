Пользователь нажимает кнопку аутентификации через ЕСИА
на данном этапе не реализовано взаимодействие с реальными госуслугами, вместо этого имитатор

Вот как аутентификации через имитатор должна работать:
в БД есть таблица esia_account, её поля: 
-- Создаем таблицу для имитации базы данных Госуслуг
CREATE TABLE esia_accounts (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    login VARCHAR UNIQUE NOT NULL, 
    password_hash VARCHAR NOT NULL,
    first_name VARCHAR NOT NULL,
    last_name VARCHAR NOT NULL,
    birth_date DATE NOT NULL , 
    gender gender_enum NOT NULL -- Используем  ENUM, который был создан ранее

);


при нажатии на кнопку "зайти через Госуслуги" мы переходим на страницу 
захода в  наш имитатор "госуслуг"(ЭТО НЕ ОТДЕЛЬНЫЙ САЙТ - это просто страница нашего приложения)
и на ней 2 поля - логин и пароль от аккаунта в "имитаторе" госуслуг.
На бэкенде мы:
1)по этим 2м полями находим пользователя и получаем из esia_account таблицы его esia_id,фамилию ,имя ,пол ,дату рождения.
Если найти не удалось - возвращаем ошибку на фронтенд.

2)Проверяем - есть ли пользователь (user),который уже привязан к этому аккаунту имитатора госуслуг(у user есть поле   esia_id UUID UNIQUE NOT NULL) 
Если такой пользователь есть - то просто запускаем его в систему(даем ему JWT)
Если нет пользователя,который привязан к этой записи,то регистрируем его
 ->создаем на их основе запись в таблице users.
(И потом только отдаем JWT) 

Регистрации в имитатор госуслуги не будет.
Пользователь в наш имитатор мы добавим через БД сами - мы сами в бд загрузим УНИКАЛЬНЫЕ комбинации логин-хэш пароля.
