
##  Фазы разработки Backend

Дмитрий, это твой roadmap. Двигайся строго по шагам, не перескакивай. У тебя дедлайн, поэтому фазы расположены от «критично для MVP» до «nice to have».

### 🟢 Фаза 1: Фундамент (2-3 дня)
**Цель:** Пустое приложение, которое запускается и подключается к БД.

1.  Создай виртуальное окружение (`python -m venv venv`).
2.  Установи зависимости: `fastapi`, `uvicorn`, `sqlalchemy`, `psycopg2-binary`, `pydantic-settings`, `python-jose`, `passlib[bcrypt]`, `python-multipart`, `aiofiles`.
3.  Создай `main.py` с базовым FastAPI-приложением и `@app.get("/")`.
4.  Настрой `config.py` (чтение `.env` через `pydantic-settings`).
5.  Настрой `database.py` (создай engine и `get_db`).
6.  **Проверка:** `uvicorn app.main:app --reload` запускается, на `/docs` открывается Swagger.

### 🟡 Фаза 2: Модели и БД (2 дня)
**Цель:** Все таблицы созданы в PostgreSQL через SQLAlchemy.

1.  Напиши все модели в `models/` по твоему SQL-скрипту (`User`, `Photo`, `Contact`, `Message`, `Partner`, `Offer`, `Promocode`).
2.  Добавь связь между `EsiaAccount` и `User` (если ты оставил её отдельно).
3.  В `main.py` вызови `Base.metadata.create_all(bind=engine)`.
4.  **Проверка:** Зайди в pgAdmin. Все таблицы появились. Никаких ошибок при старте.

### 🟠 Фаза 3: Аутентификация ЕСИА (3-4 дня)
**Цель:** Пользователь может «войти через Госуслуги» и получить JWT.

1.  Напиши `security.py`: функции `create_access_token()` и `verify_password()`.
2.  Напиши `auth_service.py`: 
    *   Функция `esia_login(login, password)` — проверяет логин/пароль в `esia_accounts`, возвращает данные.
    *   Функция `get_or_create_user(esia_data)` — проверяет, есть ли `User` с таким `esia_id`, если нет — создает.
3.  Напиши `api/routes/auth.py`: эндпоинт `POST /api/auth/esia-login`.
4.  Напиши `api/deps.py`: зависимость `get_current_user`, которая достает юзера из JWT.
5.  **Проверка:** В Swagger нажимаешь `/auth/esia-login`, вводишь тестовые данные из БД, получаешь токен.

### 🔵 Фаза 4: Профиль пользователя (2-3 дня)
**Цель:** Пользователь может смотреть и редактировать свой профиль, загружать фото.

1.  `user_service.py`: функции `get_user_profile`, `update_user_profile`.
2.  `api/routes/users.py`: 
    *   `GET /api/users/me` (с зависимостью `get_current_user`).
    *   `PATCH /api/users/me`.
    *   `GET /api/users/{user_id}`.
3.  `api/routes/photos.py`:
    *   `POST /api/photos` (принимает `UploadFile`, сохраняет в `media/`, пишет в БД).
    *   `DELETE /api/photos/{photo_id}`.
    *   `PATCH /api/photos/{photo_id}/main`.
4.  Настрой раздачу статики в `main.py` (`app.mount("/media", StaticFiles(...))`).
5.  **Проверка:** Загружаешь фото через Swagger, оно появляется в папке и в БД. Открывается по URL.

### 🟣 Фаза 5: Лента и Свайпы (3-4 дня)
**Цель:** Пользователь видит ленту и может свайпать.

1.  `contact_service.py`: 
    *   Функция `get_feed(user_id)` — возвращает список юзеров, которых ты еще не лайкал, исключая себя.
    *   Функция `swipe(initiator_id, responder_id, action)` — реализует логику `PENDING/MATCHED/REJECTED`.
2.  `api/routes/contacts.py`:
    *   `GET /api/feed`.
    *   `POST /api/contacts/swipe`.
3.  **Проверка:** Делаешь свайп, статус меняется в БД. Если два юзера лайкнули друг друга — статус `MATCHED`.

### 🔴 Фаза 6: Чаты (3-4 дня)
**Цель:** Мэтчи могут переписываться.

1.  `chat_service.py`:
    *   `get_matches(user_id)` — список мэтчей.
    *   `get_chats_list(user_id)` — список чатов с последним сообщением (сложный JOIN).
    *   `get_messages(initiator_id, responder_id, page, limit)`.
    *   `send_message(author_id, contact, text)`.
    *   `mark_as_read(user_id, contact)`.
2.  `api/routes/chats.py`: все соответствующие эндпоинты.
3.  **Проверка:** Пишешь сообщение от одного юзера, оно появляется у другого.

### 🟢 Фаза 7: Партнеры и Офферы (3-4 дня)
**Цель:** Партнеры управляют акциями, пользователи их видят.

1.  `partner_service.py`:
    *   Логика CRUD для офферов (с загрузкой фото).
    *   Логика выдачи офферов пользователям.
2.  `api/routes/partners.py`:
    *   `POST /api/auth/partner-login` (отдельная аутентификация).
    *   `GET /api/partners/me`.
    *   `POST/PATCH/DELETE /api/partners/me/offers`.
    *   `GET /api/offers` (для пользователей).
3.  **Проверка:** Партнер логинится, создает акцию. Пользователь видит её в ленте офферов.

### 🔵 Фаза 8: Инвайты и Промокоды (4-5 дней) — *Самое сложное!*
**Цель:** Работает логика «предложить свидание в кафе» с половинками промокодов.

1.  `invite_service.py`:
    *   Генерация JWT-токена (с `offer_id`, `contact_ids`, `exp`).
    *   Логика «Принять инвайт»: создать промокод, разделить на две половины, отправить два сообщения в чат.
2.  `api/routes/invites.py`:
    *   `POST /api/invites` (создать ссылку).
    *   `GET /api/invites/{token}` (проверить).
    *   `POST /api/invites/{token}/accept` (принять).
3.  **Проверка:** Пользователь А создает инвайт, Б переходит по ссылке и принимает, в чате появляются 2 сообщения с половинками промокода.

### ⚫ Фаза 9: Тестирование и полировка (2-3 дня)
**Цель:** API не падает, всё работает.

1.  Прогоняй **все** эндпоинты через Swagger, проверяй коды ответов (200, 400, 401, 403, 404, 409).
2.  Проверяй edge cases: неверный JWT, чужой photo_id, попытка лайкнуть себя.
3.  Настрой CORS (разреши `http://localhost:*` для Android-эмулятора).
